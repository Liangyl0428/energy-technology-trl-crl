# v0.2.1 严格审查与修正

结论：对象级证据门槛框架可以保留，但v0.2.0存在可复现的校验绕过与一项证据解释过度，不能只凭既有测试通过而认定评估可靠。

## 代码反例与修复

直接调用`evaluate_case`并把截止日设为2000-01-01，v0.2.0仍返回W001的TRL9。
改变该对象的配置而保留scope_id，也仍返回9。底层只校验档案哈希，依赖调用者预先过滤证据。
本版在引擎入口核对实际引用的可用日期、发表日期、引文边界与哈希，并绑定对象配置、功能、边界及证据时期。
主题检索关联不参与对象边界哈希，因此重映射不会改变成熟度。

审阅同时绑定TRL/CRL判据内容哈希，缺阶段或规则变化不能静默继承旧审阅。
加载时检查每个观测的对象/证据外键与scope，孤立观测不再被筛掉后悄然忽略。
数值测量按完整数字匹配，不再把引文中的“10”误当作“1”的实测支持。
千位分组“1,000”同样不能被截取为“1”。500主题构建保留未修改的源JSON字节，
离线回放连同输入哈希逐项对比，避免序列化差异造成来源校验不一致。
余弦关联拒绝零向量、非有限向量、缺失目录和不足三个活动中心。

`tools/bind_review_scopes.py`仅把122份既有审阅绑定到原对象与规则，不能覆盖已有不匹配绑定；
它不是独立专家复核。18份W案例原审阅日期缺失仍保持未知，不伪造日期；结果显式记录`review_date_known`。

## 实质判定修正

W011（Pelham项目26台Sunny Central Storage 2475）的引文记载合同至调试的周期、设备配置和预定用途，
没有已实现调频/无功服务的功能性能结果，也无用户价值反馈。旧判定把commissioning及main applications
当作两类成功证据，超出本仓TRL9 application及CRL2 value门槛。

本次把这两个门槛改为unknown，对应观测改为context；不伪造更低等级，也不声称现实项目技术退步。
修改依据为已有原文，未增加外部来源。其余高TRL和有界原型案例检查了现有引文；未把装机、
未来产能、年化节约估算或别的配置的表现拼接为新等级。

|结果|v0.2.0|v0.2.1|
|---|---:|---:|
|对象总数|122|122|
|TRL有值|109|108|
|CRL有值|24|23|
|同对象双轴有值|14|13|
|双轴未知|3|4|

主题关联使用新贡献标签对应的BGE中心重算；91个主题获得Top1候选案例，其余409个没有，
不表示它们不成熟。500个主题的统一TRL/CRL全部为空，所有新关联待语义确认。

## 仍不能支持的结论

724个证据消融情景重新运行；118个至少有一轴结论的对象均有来源撤除敏感性。
两个轴的删证据测试保持独立；这些是支持依赖性检查，不是等级准确率或多来源稳健性验证。
资料仅是冻结公开证据，缺独立专家金标准、来源交叉核验、完整风险清单和正式程序。
TRL5—7合格要求与TRL9工程应用采用不同阶段判据，不机械要求把所有历史阶段补齐。
正式TRL/CRL仍为空，未完成的招标量化模型、专家赋权和验收功能不能由本补丁冒充完成。
