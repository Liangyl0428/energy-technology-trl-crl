# v0.2.0 TRL/CRL一致性与灵敏度审计

`trl_crl/engine.py`、`rules.py`、`pipeline.py`与 `v0.1.0` 完全一致。
TRL沿用Q/GDW 12566—2025逐阶段证据要求，CRL沿用原5级项目规则；
不是按热点分数、专利量或向量距离赋等级。对象边界、判据及证据未更改。
此次122对象重新计算，109有TRL、24有CRL、14同对象双轴齐全、3双轴未知，
与原证据结果相比等级改变0。500主题仅建立候选关联，主题统一等级全部为空。

## 新增实测实验

见 [实验报告](../results/nmf500/experiments/REPORT.md)。

- 114个来源留一、126段证据留一、453条观测留一。
- 6种来源类型消融、各门槛支持移除及双轴独立性测试、4个可用时间截断。
- 合计724个证据情景，每个分别报告TRL和CRL；另有60组Top1/Top3、余弦/间隔、实体类型关联覆盖统计。
- 门槛支持消融把失去引用支持的门槛置未知，**不删除标准要求**。任一引用移除
  即保守撤销该门槛判定，不重新语义审核剩余证据，因此衡量当前证据包依赖性，
  不是对剩余资料可支持最高级别的估计，也不是对专家标签的准确率验证。

119个至少有一轴结论的对象，都存在移除某个来源后改变结论的情况；
109个TRL有值对象、24个CRL有值对象均受此影响。应优先补充独立支持来源。
全724情景未出现删证据后升级；去掉一轴支持没有改变另一轴。
不要只看全部122对象的高平均保持率——每次留一通常只影响少量对象，
逐对象脆弱性见 `case_fragility.csv`，具体改变见 `changed_cases.csv`。

所有126段证据的 `available_by` 都是2026-09-25；更早知识截止日全部未知。
这暴露的是历史可用日期元数据不足，不是“此前技术都不成熟”。未用发表日期
冒充当时已完成检索核读的证据。未知不当作0级，也不解释成技术退步。

映射门槛只影响候选关联覆盖，不影响对象证据等级；所有候选仍待语义确认。
94主题有Top1候选案例，不代表其余406个技术不成熟，主题TRL/CRL仍留空。

## 不依赖原始工作区的复现

```sh
python -m pip install -e . -r requirements-nmf500.txt
python pipelines/nmf500/replay.py --output /tmp/trl-nmf500
python pipelines/nmf500/experiments.py --output /tmp/trl-nmf500-experiments
python -m unittest discover -s tests -v
```

原始证据在 `data/`，500主题覆盖层在 `assets/nmf500/taxonomy_overlay/`，
重放时临时组合，不覆盖旧750输入。证据实验用原 `data/` 中相同122对象，
因为主题字段不参与等级判断。发布包含必要引用和来源URL，不含来源全文。

完整BGE映射重建仍需要相邻热点仓库及本地模型/向量，见 [NMF500.md](NMF500.md)。
Git发布标签为 `v0.2.0`；保留原Python包版本号，不将已有 `1.0.0` 元数据降版。
